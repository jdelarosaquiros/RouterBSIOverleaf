D Implementation and Configuration D.1 Shared Configuration The default configuration uses SkillSight with Qwen3.5-4B. Table 4 specifies the shared optimization settings. The retrieval budget is distinct from the downstream skill budget: the main router evaluates 50 candidates, whereas the fixed-size downstream variant supplies five skills after routing. We initialize the entire shared skill catalog and keep its membership and retrieval representations fixed while updating predicates. The length limit counts characters, including spaces and punctuation, rather than tokens. Both MBR replay and the held-out gate are enabled. The replay loss is mean Boolean error; the validation score is the single-predicate specialization described in Appendix A.4. There is no further truncation of the current-inclusive replay set. With N = 5, it contains at most 11 distinct tasks. D.2 Requests, Caching, and Reproducibility Initialization, proposals, and predicate evaluation use a single user message and a separate structuredoutput schema. The effective temperatures are one for initialization and proposal generation, and zero for predicate evaluation. In the active proposal branch, the request wrapper sets temperature one explicitly; a legacy proposal-temperature configuration field does not override this branch. For Qwen, requests disable thinking in the chat template and specify low reasoning effort. Predicate evaluation additionally supplies a 512-token thinking-budget parameter. GPT-OSS predicate evaluation instead uses low reasoning effort without treating it as a hard 512-token cap. We use a 4096-token completion allowance and a 120second ordinary request timeout. Initialization can use a separate 240-second timeout in configurations enabling that override. Each call permits at most five application-level attempts; hidden SDK retries are disabled. Invalid structured responses receive a schema reminder and, when available, trusted local validation feedback. Exhaustion terminates the call rather than creating a fabricated predicate or Boolean judgment. If the provider explicitly rejects an initialization request for context overflow, the context-recovery path can shorten the skill body to a prefix while preserving the name, description, instructions and response schema. Initialization and frozen-set evaluation each allow up to 48 workers, and repairs allow up to 48 distinct-skill jobs for the current task. These settings do not change the sequential training-task order. Exact-request responses and task–predicate judgments can be cached; generated proposals bypass the response cache.
