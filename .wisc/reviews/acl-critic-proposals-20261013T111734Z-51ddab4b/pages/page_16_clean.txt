C Benchmark and Skill Corpus Details C.1 Task Filtering and Split Construction We use the six task collections distributed with SRA-Bench (Su et al., 2026). Table 3 gives the exact task and gold-skill counts after filtering. Starting from 5,400 annotated instances, we remove any task whose required set contains a skill occurring in fewer than three remaining tasks. We recompute skill frequencies and repeat this operation until no such task remains. Filtering removes whole tasks rather than individual labels from a multi-skill task. This leaves 4,987 tasks associated with 306 distinct gold skills; 413 tasks are excluded. We target a global train/validation/test allocation of 70%/15%/15%, yielding 3,491/748/748 tasks. A constrained allocation assigns tasks while ensuring that every retained skill occurs in all three partitions. For each skill, split counts lie within floor/ceiling bounds around the target proportions, clipped to leave at least one occurrence in each partition. The allocation minimizes normalized deviations from the target proportions for both skills and datasets, and uses split seed 20260908 to order task identifiers within each dataset–gold-set group. The constraints can shift an individual dataset away from the global proportions, particularly when many skills have few examples; the exact counts therefore take precedence over an assumed per-dataset ratio. Task identifiers are disjoint across partitions, but the skill vocabulary is deliberately shared: each partition contains all 306 retained gold skills. The evaluation consequently measures generalization to held-out tasks involving represented skills, rather than to entirely unseen skills. C.2 Required-Skill Labels and Task Types Each instance has a task identifier and a nonempty annotated set of required skill identifiers. We use these released associations as the routing targets, preserving all labels of a retained task. TheoremQA concerns theorem application, LogicBench logical reasoning, ToolQA tool-use workflows, MedCalcBench medical calculators, CHAMP mathematical concepts, and BigCodeBench software-library use. All retained TheoremQA, LogicBench, ToolQA, and MedCalc-Bench tasks have exactly one annotated required skill. BigCodeBench and CHAMP also test recovery of multiple required skills. All 1,059 retained BigCodeBench tasks have multiple labels. CHAMP contains 90 single-skill and 78 multi-skill tasks. Across the six collections, the retained data contain 6,932 task–skill annotation occurrences, distinct from the 306 unique skills. The test split contains 1,097 annotation occurrences over 748 tasks: 608 tasks have one required skill and 140 have multiple required skills. The latter comprise all 123 BigCodeBench test tasks and 17 of the 26 CHAMP test tasks. BigCodeBench test tasks require between two and six annotated skills; CHAMP test tasks require between one and four. Routing recall uses the entire annotated required set as its denominator, so recovering one relevant skill does not necessarily recover all requirements of a multi-skill task. For annotation-based precision and F1, selected skills outside this set count as false positives. This convention defines the evaluation target; it does not imply that an unannotated skill cannot help a downstream agent. We do not replace a multi-skill target with a single representative label. C.3 Shared Skill Corpus and Data Access The shared SRA-Bench retrieval corpus contains 26,262 distinct skill identifiers: 636 gold skills associated with the unfiltered task collections and 25,626 web-collected distractors (Su et al., 2026). A skill record provides a name, description, and content, which may include instructions, formulas, workflows, or code. All annotated skill identifiers in the task collections resolve to records in this corpus. Filtering the task splits reduces the evaluated gold vocabulary to 306 skills; it does not reduce the shared retrieval corpus to those skills. The SRA-Bench package is publicly available as WeihangSu/SRA-Bench on Hugging Face, with the accompanying SR-Agents toolkit. The distributed dataset metadata specifies the MIT license. We retain the released skill identifiers and task-to-skill associations, allowing the same required set to be used for retrieval, routing, and oracle-conditioned downstream evaluation. 16
