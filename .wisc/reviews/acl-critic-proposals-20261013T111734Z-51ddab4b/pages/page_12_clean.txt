Let yq,s = 1[s ∈Gq]. We evaluate pf and each structurally valid candidate mp on Rs and use the binary loss from the main text, Rreplay(mp | s) = P q′∈Rs |mp(q′) −yq′,s| |Rs| . Following the main formulation, we select a minimum-average-risk option from all structurally valid candidates and the unchanged predicate: m∗ p ∈ arg min mp∈Mp∪{pf} Rreplay(mp | s). Including pf ensures that the selected average replay risk does not increase. The main formulation does not require correction of the current failure or preservation of every previously correct judgment; a minimum-risk option may trade off individual errors. It also does not require a strict replay-risk decrease or prescribe a tie-break. The resulting updates are provisional until the held-out gate at the end of the training pass. A.4 Held-Out Gate and Partial Rollback After each full training pass, we evaluate the candidate library on Tv. For skill s, the gate uses the retrieved-support set Tv,s defined in the main text and compares the candidate with the fixed coldstart predicate psi. With one predicate per skill, the implemented validation score is the mean correctness of its Boolean judgments, equal to 1 −Rv. As in the main formulation, the held-out gate uses the following strict admission rule: gstrict(Tv, m∗ p, psi) = 1[Rv(m∗ p | s) < Rv(psi | s)]. Validation ties are rejected. Let p(i) s denote the predicate at the start of the iteration, and let eps denote its value after the training pass. For changed skills, the retained update is p(i+1) s = ( eps, gstrict(Tv, eps, psi) = 1, p(i) s , otherwise. Skills without measurable validation support are also reverted. The rollback is per skill, so the retained library can contain both accepted replacements and iteration-start predicates. Comparing to psi does not ensure monotonic validation performance relative to p(i) s . Training data and replay determine predicate proposals while validation determines which updates are retained. Test data is used only for evaluation, not for predicate repair or checkpoint selection. We distinguish scores measured before validation rollback from those of the retained library after rejected updates are reverted. A.5 Optimization Procedure The update loop below follows the main minimumaverage-risk formulation in Section A.3. The retrieval corpus and task partitions remain fixed throughout optimization. 1. Initialize one predicate psi per skill, set ps ← psi, and evaluate the initial predicates on their retrieved validation tasks. 2. For iteration i = 1, . . . , I, save the iterationstart library p(i). 3. For each training task q in fixed order, register it in the global seen-task history if it is new. Retrieve its candidates and evaluate their predicates. Materialize the bounded buckets for all retrieved or required catalog skills in sorted identifier order, then identify Fq. 4. For each s ∈Fq, form the current-inclusive replay set, generate Mp replacements, and evaluate all structurally valid replacements together with the unchanged predicate. Select an option with minimum average replay risk over this full set; the unchanged predicate ensures non-increase in average risk. 5. Commit the task’s provisional repairs in deterministic skill order before processing the next task. 6. After the training pass, evaluate the candidate library on validation. For each changed skill, retain its candidate only if its validation error is strictly below the initial predicate’s error; otherwise restore its iteration-start predicate. 7. Continue to the next iteration with this partially updated library. After iteration I, freeze the retained predicates for the final routing and downstream evaluations.
