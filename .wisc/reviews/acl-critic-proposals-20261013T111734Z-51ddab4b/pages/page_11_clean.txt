A Routing and Improvement Procedure A.1 Initialization and Online Routing We initialize one predicate psi for every skill s ∈S from its public name, description, and body. The generator receives no task labels. It produces one reusable applicability statement of at most l characters. This limit also applies to subsequent replacements. Compound statements may contain AND, OR, and NOT, but they are evaluated as one predicate. The improvement procedure neither adds predicates nor decomposes them into separately evaluated clauses. For a task q, we retrieve S@k and evaluate each retrieved predicate against the public task text. Strict routing returns Pq = {s ∈S@k : ps(q) = True}. The evaluator receives only the task and predicate, not Gq, a reference answer, or the skill body. During training, required-skill annotations identify the failure set Fq = ((Gq ∩S@k) \ Pq) ∪(Pq \ Gq). A required skill outside S@k is a retrieval miss and does not trigger a predicate repair. We traverse the training tasks in their fixed split order for each iteration. For one task, repairs to distinct failed skills can execute in parallel; all results are joined before committing them in skillidentifier order. The next task is routed with the resulting predicates. This preserves sequential online updates across tasks while allowing parallel evaluator calls. For a ranked rather than strictly filtered output, the implementation orders candidates lexicographically by predicate label, retrieval score, and original retrieval order, placing true labels first. This is the operational interpretation of the label-based prioritization in the main text; it is not an unnormalized arithmetic sum for arbitrary retrieval scores. For SkillSight, the exposed score is 1/j at retrieval rank j ≥1, so adding a binary label yields the same selected-first ordering. A fixed-size top-k output may therefore include false-labelled candidates, unlike strict routing. A.2 Bounded Replay Construction For each skill, we retain two training-history buckets, H+ s and H− s , containing at most N relevant and N irrelevant tasks. Membership is determined by s ∈Gq. Before routing, each newly seen training task is registered once in a global seen-task history. After routing, we materialize the bounded buckets for every retrieved or required catalog skill in sorted skill-identifier order, including skills without a routing error. A newly materialized bucket replays the already-seen history; an existing bucket processes the new history entries. Only these perskill buckets are capacity-limited, not the global history used for lazy materialization. A bucket is filled until it reaches N entries. Thereafter, every newly seen task of that category replaces a uniformly selected existing slot. This is uniform slot replacement, not reservoir sampling: the new task is always inserted. A seeded randomnumber generator shared across buckets and the deterministic materialization order determine the replacements. Repeated visits to a task in later iterations do not insert it again. When repairing the failure on q, the effective replay set is Rs = H+ s ∪H− s ∪{q}, with duplicate task identifiers removed. Thus the historical bounds are |H+ s |, |H− s | ≤N, while the current-inclusive set can have 2N + 1 tasks if q is no longer cached. The bounds in the main replay description apply to the retained history; the current failed task is always included in the implemented decision. The proposal prompt receives the current task and its relevance label, plus up to the first three entries from each bucket, with their existing predicate judgments. Candidate scoring uses the entire effective replay set, not just these prompt examples. Bucket order, rather than a new random sample, determines the displayed examples. A.3 Candidate Admission and Minimum-Risk Selection For a failed predicate pf, we request Mp distinct replacement strings. Each must be a declarative applicability statement within the shared length limit, distinct from pf, and must preserve the singlepredicate structure.
