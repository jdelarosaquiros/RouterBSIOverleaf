Abstract
001
As agents are expected to solve broader and
002
more complex tasks, they rely on external
003
knowledge saved as skills to handle tasks be-
004
yond the LLM’s parametric capabilities. As the
005
skill corpora grows into hundreds or thousands
006
of skills, skill routing becomes a bottleneck,
007
where the agent must efficiently retrieve and
008
select the appropriate skills to complete a task.
009
Recent skill routing approaches leverage task
010
feedback to improve skill routing performance
011
online. However, feedback-driven updates to
012
routing criteria can regress performance, and
013
accumulating task feedback at scale requires ef-
014
ficient experience management. We introduce
015
a recursive self-improving algorithm for skill
016
routing in a black-box setting called RouterBSI.
017
It refines task applicability predicates using
018
Minimum Bayes Risk (MBR) with bounded
019
replay to minimize errors on seen tasks and a
020
held-out validation gate to reduce regressions
021
on unseen tasks. The router evaluates pred-
022
icates for top-k retrieved skills then selects
023
skills if the task satisfies their respective pred-
024
icate. RouterBSI improves its cold-start top-5
025
recall of required skills by 24.9% across differ-
026
ent retrievers on tasks from TheoremQA, Log-
027
icBench, ToolQA, MedCalc-Bench, CHAMP,
028
and BigCodeBench sharing a 26k skill corpus.
029
On average, it retains 90.5% of the required
030
skills in top 5 from the top 50 skills retrieved.

Introduction
032
Large language model (LLM) agents increasingly
033
rely on reusable skills to extend their capabilities
034
beyond knowledge encoded in model parameters.
035
These skills package procedural knowledge that
036
can be reused across recurring classes of tasks. As
037
skill libraries grow, however, explicitly exposing
038
every available skill in the context becomes increas-
039
ingly impractical. Recent work therefore shifts to-
040
ward Skill Retrieval Augmentation (SRA), where
041
skills must be retrieved and loaded from a large-
042
scale skill corpora (Su et al., 2026) (Figure 1).
043

In SRA, retrieval based on semantic relevance
044
alone is not enough. Skills must be invoked based
045
on their downstream utility for completing a task to
046
reliably augment the agent’s capabilities. Current
047
agents can struggle to distinguish useful skills from
048
irrelevant ones even when the correct skill has been
049
successfully retrieved (Su et al., 2026). We refer to
050
skill routing as the process of determining which
051
retrieved candidate skills are applicable to a task
052
and should therefore enter the agent's active con-
053
text for completing a task. Reliable routing must
054
distinguish applicability from semantic relatedness:
055
a skill can be topically similar to a task without
056
satisfying the requirements under which its proce-
057
dure should be invoked. This distinction becomes
058
increasingly important as broader candidate sets
059
introduce irrelevant procedures that can distract the
060
model or interfere with downstream reasoning.
061
Existing routing approaches address this prob-
062
lem through similarity scores, learned utility func-
063
tions, direct model-based selection, and explicit
064
activation conditions.
Learned retrievers and
065
rerankers can improve discrimination among can-
066
didates but encode routing criteria implicitly in
067
model parameters and require additional optimiza-
068
tion data and compute. In contrast, non-parametric
069
approaches keep the underlying model fixed while
070
modifying external state that influences future de-
071
cisions. Yet persistent external updates introduce
072
a different reliability problem. An edit motivated

Related Works
126
2.1
Non-Parametric Routing Optimization
127
Non-parametric routing optimization updates exter-
128
nal routing state from task feedback while keeping
129
model weights fixed. Experience-based methods
130
revise memories and procedures, but revisions can
131
undo earlier improvements (Wang et al., 2025b;
132
Ouyang et al., 2026; Guo et al., 2024). Structural
133
methods evolve skill relationships, but graph expan-
134
sions can introduce many irrelevant skills, reducing
135
precision or exceeding context limits (Zhang et al.,
136
2025b; Bai et al., 2026). Gated updates limit re-
137
gressions through surrogate objectives or rollback
138
criteria but don’t directly minimizing routing error
139
on seen tasks (Mi et al., 2026; Shi et al., 2026).
140
Similar to our approach, JTPRO evaluates candi-
141
dates on sampled training minibatches and held-out
142
validation but does not provide bounded experience
143
management for online adaptation (Ghoshal et al.,
144
2026). Retaining earlier routing corrections while
145
bounding experience and evaluation costs remains
146
a challenge. RouterBSI ensures non-increasing em-
147
pirical error on the retained set while bounding re-
148
play evaluation costs. A held-out gate additionally
149
rejects updates that regress validation performance
150
below the cold-start performance.
151
2.2
Parametric Routing Optimization
152
Parametric routing optimization updates model
153
weights using supervision, preferences, or execu-
154
tion feedback. Learned retrievers and rerankers
155
score relevance or utility of skill for task (Qin et al.,
156
2024; Zheng et al., 2026; Wang et al., 2026c; Li
157
et al., 2026b; Zhou et al., 2026), while direct selec-
158
tors predict which capability to invoke or whether
159
invocation is needed (Wang et al., 2025a; Qian
160
et al., 2025; Chen et al., 2026a). Reinforcement-
161
learning policies optimize skill routing from down-
162
stream rewards (Wang et al., 2026b; Xia et al.,
163
2026a; Zhang et al., 2026; Huang et al., 2026; Wu
164
et al., 2026). These approaches require large train-
165
ing data and encode routing criteria implicitly in
166
model weights. RouterBSI keeps the model fixed
167
and refines natural-language applicability predi-
168
cates that humans can inspect and edit.

Static Routing Without Feedback-driven

171
Static routing uses retrieval or inference-time selec-
172

173
from task feedback. Similarity methods retrieve
174
skills through semantic or lexical matching (Wang
175
et al., 2024; Xiao et al., 2026; Su et al., 2026),

while structured methods organize search through
177

178

2026b; Shen et al., 2023; Zhou et al., 2024). These
183
approaches support skill routing but do not convert
184
failures into persistent corrections. RouterBSI uses
185
routing failures to refine applicability predicates
186
online in a black-box setting.

Problem Definition
188
We study recursive self-improvement for skill rout-
189
ing, where an agent updates skill applicability pred-
190
icates from routing failures while avoiding regres-
191
sions. Each skill s from skill library S has a predi-
192
cate ps(q) = {True or False} indicating whether
193
it should be selected for task q. A routing failure
194
occurs when this prediction disagrees with whether
195
s from predicted skills Pq is in ground-truth set
196
of required skills Gq, producing either a missing
197
required skill or a selected irrelevant skill. Since
198
S is a large library of skills, we only evaluate the
199
predicates from skills in the top k based on retrieval
200
score r(q, Ks) between task q and the skill key Ks.
201
Given a failure in top k skills sk, the objective is
202
to iteratively update the affected predicate psk(q)
203
to reduce average replay error while using held-out
204
validation to limit regressions..

4.1
Predicate-Based Skill Routing
207

208
aligns with the type of task each skill is intended
209
to handle. This is determined by evaluating the
210
skill’s predicate statement for the given task. The
211
predicate evaluates to true when the task aligns
212
with the intended task type and to false otherwise.
213
The router first retrieves the top-k skills based
214
on the retrieval score r(q, Ks) between task q and
215
the skill key Ks. Given task q, it then evaluates the
216
predicate psk of each retrieved skill sk, where sk ∈
217
S@k, to determine whether it holds for q: psk(q) =
218
{True or False}. The router selects skills whose

Conclusion
490
We presented RouterBSI, a non-parametric opt-
491
mization algorithm for recursive self-improvement
492
that refines explicit skill applicability predicates
493
from routing failures without updating model
494
weights. It combines minimum Bayes risk selec-
495
tion over bounded replay with held-out validation.
496
Experiments on six SRA-Bench datasets show that
497
RouterBSI achieves the strongest average routing
498
performance among evaluated methods and pre-
499
serves more required skills as the selection budget
500
decreases. Ablations support the complementary
501
contributions of replay and validation and show im-
502
provements across model backbones. These find-
503
ings demonstrate the value of editable predicates
504
and feedback-driven skill routing. Future work
505
can connect skills based on dependencies to im-
506
prove skill routing performance or jointly optimize
507
predicates and skills to improve downstream per-
508
formance.

Limitations
510
Our approach has three limitations. First, training
511
is computationally expensive, although optimiza-
512
tion converges on the training data and improves
513
overall routing performance. Second, we do not
514
provide a protocol for determining which skills a
515
task requires. The method therefore relies on hu-
516
man annotations or an external labeling mechanism,
517
making optimization dependent on the availability
518
and accuracy of these labels. Third, we keep the
519
predicate checker’s instructions fixed, even though
520
errors in interpreting predicates can lead to incor-
521
rect skill selections. Our algorithm indirectly im-
522
proves checking performance by generating and
523
selecting predicate formulations that the checker
524
evaluates more accurately against labeled tasks;
525
however, it does not directly address weaknesses
526
in the checker’s instructions.
527
Ethical Considerations
528
Our experiments reuse existing SRA-Bench tasks,
529
annotations, and skill content, which may con-
530
tain errors, biases, or harmful instructions. Reuse
531
should respect dataset, skill, and model licenses,
532
while sensitive task data require appropriate ac-
533
cess controls and retention policies, particularly
534
when using external model services. Incorrect pred-
535
icate judgments can omit required skills or admit
536
inappropriate ones, propagating errors to down-
537
stream decisions. Bounded replay and held-out
538
validation assess routing behavior rather than fac-
539
tual correctness, fairness, or safety. Results on
540
MedCalc-Bench do not establish clinical validity or
541
suitability for patient care; high-stakes applications
542
require domain-specific validation and qualified
543
human oversight. Retrieved instructions and gen-
544
erated code should be treated as untrusted content,
545
with permission controls and isolated execution
546
before use.

A
Routing and Improvement Procedure
820
A.1
Initialization and Online Routing
821
We initialize one predicate psi for every skill s ∈S
822
from its public name, description, and body. The
823
generator receives no task labels. It produces one
824
reusable applicability statement of at most l charac-
825
ters. This limit also applies to subsequent replace-
826
ments. Compound statements may contain AND,
827
OR, and NOT, but they are evaluated as one pred-
828
icate. The improvement procedure neither adds
829
predicates nor decomposes them into separately
830
evaluated clauses.
831
For a task q, we retrieve S@k and evaluate
832
each retrieved predicate against the public task text.
833
Strict routing returns
834
Pq = {s ∈S@k : ps(q) = True}.
835
The evaluator receives only the task and predicate,
836
not Gq, a reference answer, or the skill body. Dur-
837
ing training, required-skill annotations identify the
838
failure set
839
Fq = ((Gq ∩S@k) \ Pq) ∪(Pq \ Gq).
840
A required skill outside S@k is a retrieval miss and
841
does not trigger a predicate repair.
842
We traverse the training tasks in their fixed split
843
order for each iteration. For one task, repairs to
844
distinct failed skills can execute in parallel; all re-
845
sults are joined before committing them in skill-
846
identifier order. The next task is routed with the
847
resulting predicates. This preserves sequential on-
848
line updates across tasks while allowing parallel
849
evaluator calls.
850
For a ranked rather than strictly filtered output,
851
the implementation orders candidates lexicograph-
852
ically by predicate label, retrieval score, and orig-
853
inal retrieval order, placing true labels first. This
854
selected-first ordering is equivalent to adding the bi-
855
nary label to the retrieval score normalized to [0, 1],
856
with ties favoring selected skills. A fixed-size top-k
857
output may therefore include false-labelled candi-
858
dates, unlike strict routing.
859
A.2
Bounded Replay Construction
860
For each skill, we retain two training-history buck-
861
ets, H+
s and H−
s , containing at most N relevant
862
and N irrelevant tasks. Membership is determined
863
by s ∈Gq. Before routing, each newly seen train-
864
ing task is registered once in a global seen-task
865
history. After routing, we materialize the bounded
866
buckets for every retrieved or required catalog skill
867
