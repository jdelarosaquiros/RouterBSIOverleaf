\subsection{Task Filtering and Split Construction}
\label{app:data-splits}
We use the six task collections distributed with SRA-Bench~\citep{su2026skillretrieval}. Table~\ref{tab:appendix-data-splits} gives the exact task and gold-skill counts after filtering. Starting from 5,400 annotated instances, we remove any task whose required set contains a skill occurring in fewer than three remaining tasks. We recompute skill frequencies and repeat this operation until no such task remains. Filtering removes whole tasks rather than individual labels from a multi-skill task. This leaves 4,987 tasks associated with 306 distinct gold skills; 413 tasks are excluded.

We target a global train/validation/test allocation of 70\%/15\%/15\%, yielding 3,491/748/748 tasks. A constrained allocation assigns tasks while ensuring that every retained skill occurs in all three partitions. For each skill, split counts lie within floor/ceiling bounds around the target proportions, clipped to leave at least one occurrence in each partition. The allocation minimizes normalized deviations from the target proportions for both skills and datasets, and uses split seed 20260908 to order task identifiers within each dataset--gold-set group. The coverage constraints can shift individual datasets away from the target proportions, particularly when many skills have few examples.

Task identifiers are disjoint across partitions, but the skill vocabulary is deliberately shared: each partition contains all 306 retained gold skills. The evaluation consequently measures generalization to held-out tasks involving represented skills, rather than to entirely unseen skills.
