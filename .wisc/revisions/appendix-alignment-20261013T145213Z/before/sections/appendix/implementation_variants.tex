\subsection{Controlled Method Variants}
\label{app:implementation-variants}
The replay-capacity settings use $N\in\{1,3,5,10\}$ per relevance category while keeping the candidate count and length limit fixed. Retrieval-budget variants use 10, 25 or 50 candidates. The corresponding current-inclusive replay bound is $2N+1$, not $N$ total.

Disabling the held-out gate retains the provisional candidate library without per-skill rollback. Disabling MBR changes selection to the first generated candidate satisfying the current-task checks; the proposal still receives retained positive and negative context. Thus this ablation removes replay-based candidate selection rather than all historical information from generation. Disabling both mechanisms combines those changes.

The alternative replay-F1 objective computes
\[
R_{\mathrm{F1}}=1-\frac{2\mathrm{TP}}{2\mathrm{TP}+\mathrm{FP}+\mathrm{FN}},
\]
with risk one when the denominator is zero. This is distinct from the default mean Boolean error and from the per-task validation predicate-pattern score. An accuracy-labelled validation variant coincides with the default validation score when every skill has exactly one predicate.
