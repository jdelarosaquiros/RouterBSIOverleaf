# Predicate-evaluator diagnostic table

This diagnostic reports model-adjudicated agreement with saved predicate decisions, not human ground truth.

## Reproduce (offline; no model calls)

From the paper directory, with the original workspace evidence available:

```sh
python scripts/generate_evaluator_validation_table.py
python scripts/generate_evaluator_validation_table.py --check
```

The first command writes only `sections/appendix/evaluator_validation_table.tex` and this directory's `counts.csv`. The second validates their exact generated bytes without writing. Neither command builds the paper or changes source experiments. The generator is standard-library-only and imports a hash-pinned historical review module solely for read-only evidence/journal validation; it never calls its `main`, enters its writer context, creates a client, or opens credentials. SQLite is opened read-only by the historical validator. Bytecode writes are disabled.

The source manifest contains original absolute evidence paths, so the full original evidence must remain available there. `--workspace-root` locates the sidecar's relative source paths; it does not rewrite historical manifest paths. Missing or changed evidence fails closed. This intentionally is not a standalone experiment-reproduction package.

## Three distinct provenance layers

- Paper artifact: `../evaluator_validation_table.tex`, included by `../evaluator_validation.tex`.
- Display data: `counts.csv`, programmatically selected from exact saved summary fields in `summary_excerpt.json`. Raw source fields `correct` and `accuracy` are displayed as agreements and agreement proportion, not human correctness.
- Historical data producer: `project_skill_selection/BayesGSI/scripts/review_predicate_evaluations.py`; exact script hash and source review directory are in `provenance.json`. Table rendering is done by the new paper generator, not by rerunning model adjudication.

`provenance.json` pins the saved summary, manifest, success/error journals, historical validator, latest 40-case audit evidence, and previous excluded sample. The saved summary excerpt is validated against the exact current pinned summary on every invocation. No task text, predicates, or individual rationales are copied into these sidecars.

## Checks and interpretation

The generator verifies all consumed-source hashes, reconstructs source occurrences and saved SQLite judgment evidence, checks the full manifest, verifies every success/error journal record hash and request payload, and reconstructs all occurrence-weighted summary fields (including per-task/per-dataset counts and the confusion matrix). It then reproduces the seeded nonoverlapping audit sample and reconciles its stratum counts. Sources are hash-checked again before output.

Counts weight all 37,400 occurrences, while the journal contains 37,350 distinct task/predicate/saved-Boolean reviews. The pooled row sums counts before dividing; it is not an unweighted dataset mean. Agreement percentages use two decimals, no rankings or dispersion estimates. Dataset order follows the established paper aliases: TheoremQA, LogicBench, ToolQA, MedCalc-Bench, CHAMP, BigCodeBench.

Prose diagnostics derive from the saved confusion matrix: provisional reference-positive recall is `709 / (709 + 611)`; always-False reference agreement is `(35606 + 474) / 37400`. These are not measures against human ground truth. The latest audit has 20 reviews in each first-review correctness stratum, excludes the prior 20 IDs, and uses seed 20261014. Results are 17 supported/1 likely incorrect/2 ambiguous in the error stratum and 20 supported in the correct stratum. Its blinded second AI pass is not a human study; all correct-stratum saved labels were False. Do not combine the samples or interpret the balanced sample as representative adjudicator accuracy.
